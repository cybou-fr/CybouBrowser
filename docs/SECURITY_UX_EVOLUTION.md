# CYBOU — безопасность и UX: следующий этап

**Актуализировано:** 17 октября 2026. **Основа аудита:** `main` @ `51559ca33e089eeebca3edfb49dff05710d1d84c` + tracker exception commit `9f7b69887a6ca7bdfbf6c1ef31c249b8cc9a2e0f`.  
**Статус:** план развития продукта и спецификация приёмки. Планы ниже **не реализованы**, если прямо не указано обратное.

## Продукт, который мы строим

**CYBOU — браузер наблюдаемого и управляемого веба.** Он должен помогать понимать, что недоверенная страница просит сделать, что ей действительно разрешено, что было заблокировано и как временно изменить поведение — без постоянных положительных разрешений сайтам и без навязчивых ASK-диалогов.

### Неизменяемые границы

1. **Все 11 индивидуальных кнопок Control Bar остаются в одной существующей навигационной строке.** Ни второй строки, ни трёх групповых значков. URL заполняет оставшуюся ширину и доступен для редактирования по клику / Ctrl+L, не вытесняя иконки.
2. **Интерактивные стеклянные hover-панели сохраняются.** Наведение открывает правильную capability, перевод курсора на карточку сохраняет её открытой, соседняя кнопка мгновенно меняет содержание. Не заменять их plain ToolTip.
3. **Прямое действие по клику:** один клик управляет разрешённым переключателем или конкретным действующим permission request. Для невозможного действия интерфейс честно объясняет ограничение.
4. **Нет Always Allow и пользовательского ASK.** Внутреннее `AskEveryTime` Qt не является UI-политикой. Отсутствие ответа всегда ведёт к отказу.
5. **Нет выдуманных событий:** запрос, политика, grant, блокировка и физическая запись — разные состояния. `grant != camera recording`. Сетевой лог профиля нельзя выдавать за точный счётчик вкладки.
6. **Исключения ограничены:** текущий запрос/документ/контекст/время. Блокировки транспорта, критические настройки WebEngine и защищённые permissions не отключаются из Network-карточки.
7. **Временный off-the-record профиль — изоляция данных**, но не доказательство отдельного процесса или прокси/анонимности.

## P0 — безопасность до новых функций

### 1. Одинаковая политика для верхней страницы и стороннего iframe

**Конкретный разрыв:** `ControlBarController::setPermissionPolicy()` сохраняет explicit deny для origin текущей страницы, а `shouldDeny()` ищет его по `permission.origin()`, который у cross-origin iframe другой. Это не означает автоматический grant (он всё равно требует актуального запроса и подтверждения), но пользовательский запрет может не распространиться на iframe.

**Требование:** запрет top-level site распространяется на вложенные requester origins; дополнительные запреты requester действуют независимо. В UI честно показываются оба origin. Разрешение по-прежнему проверяет request ID, объект native permission, tab UID, профиль и navigation epoch. Не ослаблять fail-closed политику.

**Тест:** страница A с iframe B, блок A, блок B, независимые вкладки и private profile, смена epoch и запоздалый клик, комбинированные camera/mic. Успех — отсутствие обхода явного запрета и отсутствия гранта без нового согласия.

### 2. Временные разрешения без неожиданного уничтожения работы

**Сегодня:** спустя 60 секунд после каждого grant срабатывает независимый deadline; earliest expiry уничтожает весь WebEngineView. Это консервативный способ гарантированно разрушить документ с правами, но он может неожиданно обрывать видеозвонок, форму, воспроизведение.

**Цель:** сохранить ограниченный доступ и отсутствие бессрочного доверия, но не ставить пользователя перед внезапным обрывом. *До изменения механизма* протестировать настоящий микрофон, камеру, комбинированную запись, iframe, фоновые вкладки, закрытие, sleep/resume и поведение Qt WebEngine при revoke. Если безопасного подтверждённого прекращения потока без уничтожения документа нет, не объявлять revoke «мгновенным»; текущий fail-closed teardown сохранять до доказанного альтернативного пути.

Проектируемое UX-решение — ненавязчивый остаток времени/предупреждение, понятные последствия завершения, **явное ограниченное продление именно текущего документа** только при проверенной реализации. Автопродление, Always Allow и перенос права на следующую страницу запрещены.

**Тест:** длительный видеозвонок 5–30 мин, два независимых grants, явный stop, expiration, navigation, close, OS suspend/resume. Для целевой реализации нет тихого обрыва, без ослабления защиты.

### 3. Защита и обновление самого WebEngine

Поддерживаемая и своевременно патченная Qt WebEngine/Chromium, включённый sandbox, проверка release flags и запрещённых insecure arguments; тестировать URL schemes, TLS/mixed content, permission boundaries, downloads после каждого обновления. Политика безопасной доставки/подписи обновлений ещё отсутствует. Нельзя считать браузер защищённым потому, что версию движка показывают в About.

**Gate:** реальные runtime версии и sandbox проверены, security+smoke regression успешны; план поддерживаемых релизов, проверка целостности дистрибутива и обновлений.

## P1 — безопасность, заметная каждый день

### 4. Полноценный движок сетевой фильтрации

Заменить маленький статический список известных доменов версионированными правилами рекламы и трекеров. Раздельные категории показывать **лишь при обоснованной классификации**; unknown не объявлять ad/tracker. Immutable индексированные snapshots в interceptor без тяжёлого парсинга и QML вызовов на каждую сетевую операцию. Проверяемая целостность/происхождение обновлений, атомарная активация и rollback. Проверять false positives на логине, видео, оплате, CAPTCHA, CDN и интегрированных виджетах.

Приоритет правил: обязательные транспортные/URL-security denies **всегда выше** временных исключений фильтра. Network filtering не должен отключать sandbox, HTTPS strict или правила работы устройств. Если не умеем cosmetic/DOM blocking, не называть сетевой фильтр полной косметической блокировкой рекламы. Не отправлять историю посещений/полные URL третьей стороне без отдельного решения и согласия.

### 5. Развить уже существующее tracker exception до двух независимых политик внутри Network-карточки

**Существующий шаг уже реализован:** `TrackerExceptionLease` по согласию пересоздаёт одну HTTPS-страницу в отдельном off-the-record профиле, временно пропускает известные tracker-list запросы с совпадающим firstParty, показывает countdown и позволяет revoke. Исключение заканчивается при reload, navigation и expiry, без наследования соседними вкладками; обычные cookies/cache не копируются. Это честное, но заметно влияющее на UX ограниченное решение: при окончании 60 секунд уничтожается документ. Это **не** независимые Ads и Trackers и не полнофункциональный ad blocker.

**Будущий шаг:** не добавлять вторую строку или новые обязательные иконки. В существующей интерактивной карточке Network после реализации классификации — независимые действия «Реклама» / «Трекеры» и перечень подтверждённых блокировок.

Исключения действуют лишь для заданных `tabUid + topOrigin + profile + navigationEpoch` и конечного срока; переключение одной категории не меняет другую или остальные вкладки. Закрытие/изменение site/expiry восстанавливает default. Если для применения нужен reload, UI показывает это и предлагает действие. Undo хранит типизированный исходный контекст и не применяется к чужой вкладке. Глобальные переключатели — только в Settings; сейчас Network-карточка намеренно не даёт отключить blocker глобально.

**Gate:** две вкладки одного origin и ещё одна другого; ads-off ≠ trackers-off; timed expiry, reload, Undo, tab switch, strict HTTP unchanged; проверка фактических network outcomes.

### 6. Семантика и достоверная история событий

Сегодня `ControlBarIcon.qml` использует `brandColor` для ALLOW; камера может стать красной при разрешении, хотя красный уже используется для блока. Отделить цвет продукта/типа кнопки от **effective policy** и **observed activity**:

| Смысл | Предлагаемая индикация | Не означает |
| --- | --- | --- |
| Нет доступа по умолчанию | нейтральный серо-синий | опасность / произошедшее событие |
| Получен действительный запрос | янтарная подсветка / «!» | grant |
| Выдан временный grant | спокойный зелёный маркер | физическая работа устройства |
| Реально блокировано действие | отдельный красный event-маркер | все действия данного сайта вредоносны |
| Эффективен фильтр | холодный сине-бирюзовый индикатор | 100% защита |
| Нужен reload / статус unknown | отдельная форма и текст | доказанная безопасность |

Не опираться только на цвет; проверить доступность клавиатуры, reduced motion и дальтонизм. `ActivityAggregator` должен объединять разрешения, popups, transport и проверенные сетевые блокировки как короткие записи в памяти с ограничением объёма и TTL. Событию присваивать честный scope: `tab`, `profile`, `unknown`. `RequestObserver.firstParty` **не доказывает** конкретную вкладку. Никаких URL paths, query, headers, bodies или токенов в журнале.

**Gate:** иконка камеры не окрашивается красным только из-за ALLOW; pending/grant/block различимы; профильные события не приписаны вкладке; burst не тормозит QML.

## P2 — предотвращать опасные переходы до выполнения кода

### 7. Navigation Guard

Локальные проверяемые признаки: подмена IDN/Unicode confusables, подозрительная структура адреса, redirects/scheme downgrade, запросы страницы к LAN/loopback/private-network с проверкой IPv4/IPv6 и DNS rebinding, опасные внешние схемы и инициаторы загрузок. Не выдавать неизвестный домен за автоматически вредоносный. Никаких постоянных тревожных попапов без существенного доказательства угрозы. Не отправлять посещённые URL на внешнюю оценку репутации по умолчанию.

**Gate:** позитивные и негативные fixtures IDN, redirect, private-network; объяснимый блок, минимальные false positives, отсутствие URL exfiltration. Это не гарантия защиты от фишинга.

### 8. Restricted Browsing

При подтверждённом высоком риске применять отдельный ограниченный контекст: **JavaScript выключен до первой загрузки документа**, permissions deny, строгое управление popups/downloads/private-network и объяснение человеку. Профильные cookies/cache отделены, но это не доказательство изоляции renderer/process. Прокси-маршрутизация — только после отдельных DNS/WebRTC/route leak tests; в отсутствие доказательств не писать «анонимно» или «изолировано от эксплойтов».

## Очерёдность и документальные обязательства

1. Исправить top/requesting origin deny и тесты iframe.
2. Провести реальные media/lease испытания; спроектировать UX предупреждения/отзыва без auto-grant.
3. Укрепить релизный WebEngine patch/sandbox/update процесс.
4. Реализовать RuleEngine и настоящий backend-контракт категорий.
5. Развить уже работающий tracker-only exception в независимые временные Ads/Trackers действия в **существующей Network hover-панели**, сохранив строгую модель безопасности и улучшив UX.
6. Сделать activity aggregation и единый семантический слой индикации.
7. Реализовать Navigation Guard, затем проверенный Restricted Browsing.
8. Изоляция процесса/прокси — исследование после проверки угроз и сетевых утечек.

**Разработка:** небольшими последовательными коммитами непосредственно в `main`, без веток; локальная сборка и регрессионные тесты до отметки implemented/tested. GitHub Actions пока не обязательны.
