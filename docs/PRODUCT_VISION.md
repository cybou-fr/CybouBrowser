# CYBOU — наблюдаемый и управляемый веб

Нормативное продуктовое направление, 16.10.2026. Observe → Restrict → Control → Revoke.
CYBOU показывает доступные возможности страницы, обнаруженные запросы и подтверждённые блокировки. Каждая из 11 возможностей имеет постоянно видимую кнопку. URL доступен по клику и Ctrl+L, но не вытесняет управление.

## Инварианты
Чувствительный доступ недоступен без конкретного запроса. Нет Always Allow, сохранённого положительного доверия origin и пользовательской политики ASK. Запрос, политика, выдача разрешения и фактическое использование — разные состояния. Отказ по таймауту безопасен. Запрос стороннего iframe показывает requesting origin; top origin не подменяет его.

Положительные исключения временные. Закладки, история, cookies и обычное хранилище могут сохраняться: это данные браузера, а не разрешение использовать устройство. Приватные окна используют независимые профили.

## Сценарии
Страница просит микрофон: кнопка показывает запрос и requesting origin в стеклянной hover-панели; клик разрешает текущий запрос. Без реакции через 15 секунд запрос отклоняется. По истечении самого раннего минутного доступа документ выгружается переходом на about:blank. Повторный запрос требует нового действия.
JavaScript отключается кнопкой, баннер предлагает перезагрузить страницу или отменить изменение в исходной вкладке. Редактирование адреса оставляет возможности видимыми.

## Границы
Не обещаем наблюдение всего DOM/JS, запись камеры на основании grant, полную блокировку рекламы или защиту от любого phishing. Полноценные списки правил, risk engine и проверенная прокси-изоляция ещё требуют реализации. Временный HTTP opt-in реализован в отдельном профиле на 60 секунд. Разделение статусов: [ROADMAP](ROADMAP.md).

## Следующая цель: безопасность, видимая без сложных настроек

Архитектура текущего продукта уже определена: 11 иконок inline в одной навигационной строке, URL занимает остаток места, стеклянные интерактивные карточки открываются по hover и остаются доступными для действий. Изменять этот UX ради «новой защиты» не следует.

В центре следующего этапа — **закрыть разрыв между наблюдением и реальным предотвращением**. P0: распространение явного отказа верхней страницы на сторонние iframe, проверенный жизненный цикл реального media и защита обновлённого WebEngine; P1: полноценные независимые Ads/Tracker правила, временные per-site исключения *в существующей Network-карточке*, честная активность и семантика цветов; P2: осторожный локальный Navigation Guard и ограниченный режим до загрузки. Эти возможности **запланированы, но пока не реализованы**.

Сохранить отсутствие постоянного доверия: никаких Allow Forever, автоматической пролонгации чувствительных разрешений и глобального выключения защиты из карточки сайта. Отсутствие сетевого события не равно безопасности, grant не равно записи устройства, отдельный профиль не равно process/proxy isolation.
