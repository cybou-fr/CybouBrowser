# ADR 0007 — выбираемая экосистема облачных сервисов

**Статус: РЕАЛИЗОВАНО (C++/QML Core, Settings, NewTab App Launcher, Tests).** Решение владельца CYBOU Browser, 17 октября 2026 года. Интеграция выполнена как собственный модуль `src/cloud/`, QML компоненты `CloudSettingsSection.qml`, `CloudAppLauncher.qml`, `CloudAppTile.qml`, с полным покрытием unit-тестами `CloudCoreTests.h`. Это не сообщение о партнёрских соглашениях с вендорами.

## Решение

**Облачная экосистема выбирается пользователем из списка — аналогично поисковой системе.** В новом профиле по умолчанию выбрана **Proton**. **Google Workspace и Microsoft 365 (в том числе пользовательские аккаунты Microsoft; название Office 365 может встречаться в интерфейсах и документах) являются полноправными альтернативами**, не исключениями из политики CYBOU. Остальные провайдеры представлены честно, по реально доступным веб-приложениям.

Выбор облачной экосистемы **не связан** с выбором поисковика. Выбор по умолчанию не означает автоматическую авторизацию, фоновую загрузку сервисов, передачу данных или обязательное использование Proton. Пользователь может сменить поставщика в любой момент либо отключить облачные ярлыки («Без облачной экосистемы»). Любой другой сайт и сервис доступен через обычный ввод URL независимо от выбранного провайдера.

Коммерческое партнёрство может влиять на открыто обозначенные предложения, **но не на правила безопасности, состав разрешений или ограничение выбора**. Не называть CYBOU официальным браузером Proton, Microsoft или Google без соответствующего соглашения.

## Каталог провайдеров и роли

Первый этап реализации каталога:

| --- | --- | --- | --- | --- | --- | --- |
| `proton` **(default)** | Proton | Proton Mail | Proton Drive | Proton Calendar | Proton Docs / Sheets (через Drive) | Proton Meet |
| `google` | Google Workspace / Google apps | Gmail | Google Drive | Google Calendar | Docs / Sheets / Slides | Meet / Chat |
| `microsoft` | Microsoft 365 (Office 365) | Outlook | OneDrive | Outlook Calendar | Word / Excel / PowerPoint (web) | Teams |
| `infomaniak` | Infomaniak kSuite | Infomaniak Mail | kDrive | Calendar | Онлайн-документы в kDrive | kMeet / kChat |
| `zoho` | Zoho Workplace | Zoho Mail | WorkDrive | Zoho Calendar | Writer / Sheet / Show | Zoho Meeting / Cliq |
| `nextcloud` | Nextcloud Hub, свой сервер | Mail (если установлено) | Files | Calendar (если установлено) | Nextcloud Office (если установлено) | Talk (если установлено) |

**Следующий этап каталога:**

- **Apple iCloud:** iCloud Mail, Drive, Calendar, Pages, Numbers, Keynote, если доступно в веб-версии с данным типом аккаунта.
- **Специализированные файловые сервисы:** Dropbox, Box, pCloud, Tresorit — только роль «Файлы», без выдуманной совместной почты, календаря или офисного пакета.
- Возможность выбрать **разных поставщиков для разных ролей** (например, Proton Mail + OneDrive) после проверки спроса. Это не блокирует обычное одновременное открытие сайтов разных компаний уже в первом этапе.

У провайдера могут отсутствовать некоторые сервисы, требоваться тариф, отдельный аккаунт или серверный модуль. Каталог должен показывать только подтверждённые функции, корректные названия и официальные HTTPS-точки входа. Никакой выдуманной «общей учётной записи CYBOU» или обещания общего SSO между разными вендорами.

## Продуктовый UX

- **Settings → Cloud services:** селектор выбранной экосистемы; `Proton` при отсутствии пользовательского выбора; `None` для отключения ярлыков; смена действует немедленно для каталога, без перезагрузки всего браузера.
- **Alpine Dawn / новая вкладка:** компактное необязательное пространство с иконками *реально доступных* сервисов выбранного провайдера. Переход по иконке открывает **официальное веб-приложение в обычной вкладке**, не privileged webview, не скрипт внутри browser chrome.
- **Управление вкладками:** по желанию закрепление сервисов как обычных вкладок, открытие ссылок и восстановление пользовательского рабочего набора через существующий browser session mechanism. Никаких автоматических логинов/запусков/пингов поставщика при старте.
- **Смена провайдера:** не удаляет вкладки, историю, cookies, профили или сессии и не меняет search engine, HTTPS, permissions или privacy settings. Просто меняет каталог ярлыков и будущие действия облачного workspace.
- **Nextcloud self-hosted:** пользователь явно вводит свой базовый HTTPS URL. Показать реальный host и проверять синтаксис/scheme; не разрешать `file:`, `javascript:`, `http:` или встраивание credentials в конфигурацию. Никакой автоматической trusted-origin привилегии; доступность приложений зависит от сервера.
- Возможность использовать любой поддерживаемый сайт Google/Microsoft/Proton даже если он не выбран в селекторе; «Провайдер по умолчанию» — удобство, **не allowlist посещений**.

На первом этапе достаточно **быстрых официальных веб-переходов**, без дополнительных privileged integrations. Более глубокие операции (сохранение в облако, синхронизация, API) — отдельные предложения и отдельные security gates.

## Безопасность, независимость и монетизация

Нормативное решение [ADR 0006](0006-no-third-party-extensions.md) действует без исключений: **никаких сторонних browser extensions, Proton Pass/Google/Microsoft plugins, внешних CLI в комплекте, userscripts или загружаемых исполняемых пакетов**. Каталог — собственные C++/QML **неисполняемые данные + обычные HTTPS-навигации**.

- Аутентификация, 2FA, OAuth-сессии и хранение паролей принадлежат **официальным сайтам поставщика и WebEngine**, CYBOU не собирает и не хранит их токены для каталога.
- **Никаких особых permissions** Proton или любого иного провайдера; Control Bar применяет те же правила, что к другим сайтам. Не изменять HTTPS strict, фильтры, JavaScript policy или cookie policy ради партнёрской страницы.
- Не внедрять browser-owned JS в страницы почты/документов; не считывать их содержимое и не строить «параллельное» API над веб-интерфейсом.
- Метаданные каталога локальные и проверяемые, без remote configuration, способной подменять URL исполняемым кодом. Изменение endpoint в новой версии — предмет review. Открывающиеся ссылки могут перенаправлять по правилам самой сети; CYBOU сохраняет обычные проверки переходов.
- Affiliate-ссылки/спонсорство допустимы **только отдельно и явно обозначены**; обычные переходы «Mail/Drive/Calendar» не подменяются коммерческим redirect/трекером. Сведения об аккаунте и истории просмотра не передаются партнёрам ради комиссии.
- Не выдавать наличие ссылки в каталоге за договор, сертификат безопасности или протестированную совместимость с данным Qt WebEngine.

## План и приёмка (ещё НЕ реализовано)

1. `CloudProviderCatalog` (статический встроенный список): стабильный ID, отображаемое имя, поддерживаемые категории, официальные проверенные URL и признак отсутствующей роли. `CloudProviderPreferences` — сохранённое `selectedProvider`, где default=`proton`, независимое от `searchEngine`.
2. UI в Settings и Alpine Dawn, не меняя навигационную строку или **11 интерактивных иконок Control Bar**. Текущие вкладки и существующие cookies после смены поставщика не трогать.
3. Проверки обычной web-навигации, авторизации, redirects, отсутствия prefetch к провайдеру до клика, приватного режима, locale FR/RU, narrow/DPI, отсутствующих сервисов.
4. Проверки security boundaries: no extension/CLI, no special permissions, no scripts injected into cloud sites, provider switch cannot mutate search, history, downloads, session, cookies or security settings; строгая проверка Nextcloud endpoint.
5. **Реальную совместимость WebEngine с каждым веб-приложением** записывать отдельным PASS/FAIL/SKIP на поддерживаемой Windows Qt-версии. Не объявлять интеграцию готовой только из-за удачного открытия landing page.
