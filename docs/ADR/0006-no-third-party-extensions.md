# ADR 0006 — запрет сторонних расширений и минимизация исполняемых зависимостей

> **Версия продукта:** `0.3.0-alpha.1` — engineering alpha, не квалифицированный релиз. Старые тесты и названия `0.8` не доказывают безопасность текущей сборки. [VERSIONING](../VERSIONING.md) · [RELEASE_CRITERIA](../RELEASE_CRITERIA.md) · [SECURITY_VERIFICATION_FRAMEWORK](../SECURITY_VERIFICATION_FRAMEWORK.md).

**Статус: ПРИНЯТО.** Решение владельца CYBOU Browser, 17 октября 2026 года. Обязательный контракт для всех релизов, модулей, партнёрств и планов развития.

## Абсолютный запрет сторонних браузерных расширений

CYBOU **не устанавливает, не загружает, не исполняет, не распространяет и не обновляет сторонние браузерные расширения**: Chrome/Chromium extensions, CRX, WebExtensions, Manifest V2/V3, сторонние browser plugins и привилегированные userscripts, независимо от автора, подписи, репутации или партнёрского договора.

**Не разрабатывать** магазин расширений, менеджер установки, side-loading, расширяемый совместимый runtime, background extension processes, privileged third-party content scripts либо скрытый переключатель «включить extensions». Запрет включает Proton Pass extension и аналогичные расширения любых партнёров. Подпись или проверка поставщика не превращает постоянно обновляемый сторонний код в доверенный.

Для исполнения этого решения при дальнейшей разработке не использовать `QWebEngineExtensionManager` для установки/загрузки расширений или альтернативные loaders с тем же эффектом. Статическая и runtime проверка отсутствия таких путей — **релизный gate, а не уже подтверждённый результат тестирования**.

## Исследовать лучшие функции, но разрабатывать самим

Разрешено анализировать популярные расширения, функции других браузеров и успешные UX-паттерны, чтобы составлять собственные требования и тест-кейсы. Реализовывать полезные функции **собственным сопровождаемым C++/Qt/QML-кодом CYBOU** в существующих моделях permission, network, page lifecycle и Control Bar. Не копировать чужой код, assets или защищённые технологии без прав и соблюдения лицензий.

Нельзя переупаковать стороннее расширение или скачать remote executable и назвать это «нативной функцией». Никаких привилегий веб-сайту просто потому, что мы позаимствовали идею его расширения.

## Минимизировать сторонние executable и supply-chain risk

Необходимо различать **встроенный программный стек** и **сторонние расширения**:

- Qt, Qt WebEngine/Chromium, системные библиотеки и необходимые runtime-компоненты являются сторонними зависимостями браузера и должны поддерживаться, обновляться и проходить проверку; их нельзя выдавать за отсутствие стороннего кода.
- Обычный JavaScript сайтов запускается движком как **недоверенный веб-контент в соответствующем ограниченном контексте**, а не как расширение или часть browser-owned chrome. Запрет extensions не отменяет отдельную угрозу web content.
- Для каждой новой исполняемой зависимости: обосновать необходимость, минимальные полномочия, происхождение, версию, лицензию, состав, поддержку, угрозы, обновления и тестирование. По умолчанию **не включать в поставку сторонние CLI, агенты, демоны, плагины, фоновые процессы и загружаемые исполняемые модули для необязательных функций**.
- Правила рекламной/трекерной фильтрации допускаются только как проверяемые **неисполняемые данные**, без загрузки скриптов/кода из подписок.
- Открытие уже скачанного файла системным приложением по **явному подтверждению пользователя** — отдельная граница в рамках существующей download policy, не право CYBOU незаметно установить или запустить партнёрский бинарник.

## Proton и любые другие партнёры

Сервисы Proton Mail, Drive, Calendar, Docs, Pass, VPN и любые другие обслуживаются как обычные сайты с общими правилами CYBOU. Опциональные native-интеграции возможны только на базе собственного кода и документированного узкого API после отдельного анализа безопасности и явного действия пользователя. **Ни статус Proton, ни revenue-share не дают исключения из запрета расширений**, особых device permissions или доступа к cookies, паролям и истории. Не включать Proton Pass extension или Proton Drive CLI в обязательный пакет.

## Приёмка

1. При архитектурном review и сборке проверять отсутствие extension store/manager/loader/installation/update, runtime загрузки пакетов расширений и обходных privileged injection paths.
2. Вести перечень сторонних исполняемых компонентов и обновлять его при каждой новой зависимости; проверять происхождение, CVE/patches, лицензии и реальный runtime sandbox.
3. Любую заимствованную **идею** реализовывать и тестировать собственным кодом, без стороннего исполняемого extension package.
4. Если предложение противоречит запрету, отклонять его. Изменить правило может только **новое прямое решение владельца проекта**.

Выбираемый cloud provider не отменяет это решение: [ADR 0007 — Cloud Services](0007-selectable-cloud-services.md).
