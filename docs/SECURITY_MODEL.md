# Модель безопасности

## Граница доверия
Веб-страница и iframe недоверенные. Browser-owned QML получает QWebEnginePermission и разрешает только действительный объект запроса. PermissionCoordinator реализован в C++; QML передаёт native request и отображает сигналы. SiteContext содержит слабые ссылки на view/profile, tab UID, top/requesting origin и navigation epoch.

Оба профиля используют AskEveryTime; координатор отказывает, если фактический профиль view сменился или больше не использует эту политику. Это механизм движка, не диалог пользовательского интерфейса. Controller не выдаёт grants через queryPermission. Старые controlPolicies удаляются; новые поведенческие исключения хранятся в памяти отдельно по tab UID и origin. Запреты не означают остановку уже работающего устройства.

## Жизненный цикл
Каждый запрос имеет монотонно возрастающий ID; resolve требует точного совпадения ID. Кнопка фиксирует ID при нажатии и передаёт его при отпускании, чтобы отложенный клик не разрешил другой запрос. Одновременно ожидает один запрос окна; неподдерживаемые и фоновые запросы отклоняются. Timeout 15 секунд. Перед grant проверяются объект вкладки, профиль, tab UID, top origin, requesting origin и navigation epoch, а также абсолютный deadline и валидность native request. Смена вкладки, навигация основного фрейма, закрытие вкладки и окна отменяют ожидание. Навигация/закрытие уничтожают документ с доступом; для каждого grant создаётся независимый минутный PermissionLease. Новый grant не продлевает ранние deadlines. По самому раннему истечению WebEngineView уничтожается, на том же месте создаётся пустая вкладка с новым UID; закрепление и mute сохраняются. Страница не может отменить этот teardown через beforeunload. Все grants старого документа удаляются. Используются monotonic deadline и wall-clock ceiling; задержка GUI-таймера не позволяет разрешить просроченный запрос. Подтверждённая замена документа снимает leases старой эпохи; ошибка загрузки не отменяет их защитный срок. Очистка разрешений также уничтожает views с grants. Клик сброса на чувствительной capability без pending request заменяет view на свежую с тем же URL, не выдавая никаких прав и не добавляя вкладку.

## Сеть
HTTPS strict постоянно включён в production; старый глобальный opt-out удаляется. Сетевая панель разрешает конкретную заблокированную HTTP-навигацию в новом off-the-record профиле без обычных cookies/cache. Исключение живёт максимум 60 секунд: один точный main-frame URL, включая query, затем только HTTP-ресурсы того же origin с совпадающим firstParty. Другие HTTP origins, ws и URL с credentials запрещены. Reload/следующая навигация уничтожает контекст; HTTP требует нового подтверждения. Переход не воспроизводится автоматически в обычном профиле. Отзыв и истечение срока уничтожают view и профиль, сохраняя положение вкладки. Это изоляция данных профиля, не отдельный процесс или proxy. HTTPS-First предлагает исключение после ошибки только для известной исходной HTTP-попытки с совпадающей эпохой; TLS-ошибки всегда отклоняются. Тестовый opt-out доступен лишь специальным CLI harness в отдельной организации настроек.
Статический suffix-list блокирует часть сторонних сетевых запросов. Сетевые события имеют профильную область: firstParty не доказывает конкретную вкладку. Храним только origin, firstParty origin, тип, время, результат и причину; никаких path/query/headers/bodies.

## Не гарантируется
Нет достоверного датчика использования camera/mic, доказанной per-tab proxy изоляции, оценки вредоносности неизвестного сайта и полного отзыва всех native разрешений без выгрузки документа. AskEveryTime и iframe/media lifecycle необходимо проверить на реальных сайтах Qt 6.12.
